# Backend integration changes

Compared with the latest `Capstone_3.zip`, packages and domain relationships are unchanged. The HTTP paths/methods are unchanged. No business pricing, reservation, completion, assessment cutoffs, bonus/redemption rules, or provider credentials were moved into the frontend.

1. **`application.properties` and `.env.example`:** Replaced the uploaded database password and service sender/host values with environment configuration. Disabled SQL/stack trace output, configured HttpOnly/SameSite cookies, explicit allowed origins and 10 MB upload limits. No original credential value is committed.
2. **`Config/WebIntegrationConfig.java`:** Added credentialed CORS and a session-based HTTP interceptor. Public catalog/discovery and account entry endpoints remain available. Maintenance list/create/delete/update operations require ADMIN, with explicit ownership exceptions for member profiles, offers, requests, owned-skill removal, sessions and participant agreements. Mutations require the API client's custom header and trusted browser origin, mitigating simple-form/cross-origin CSRF. The direct score-taking endpoint is restricted to ADMIN because ordinary members otherwise could submit their own verification grade; member verification uses the uploaded AI generation/evaluation flow. Existing service ownership checks remain authoritative for workflow endpoints.
3. **`Model/Account.java`:** Password serialization is ignored. Password storage/matching remains the uploaded behavior; it has not been migrated or represented as hashed.
4. **`AccountService.getFullProfile`:** Added a minimal ADMIN profile to the existing profile endpoint so session restoration can identify administrators. Individual/company response DTOs are unchanged.
5. **`Model` read-only getters:** Added association IDs for account skills, skill offers, learning requests, sessions, reviews, participants and transactions, plus skill names for raw offers/requests and a boolean `zoomLinked` for sessions. These expose identities/status needed by forms without changing JPA relationships, returning passwords, or exposing Zoom credentials. Existing DTO fields are unchanged.
6. **Agreement integration:** Added saved `content` to the existing participant-protected acceptance-status response. Agreement add/update controllers verify participant access and prevent moving a shared-primary-key agreement to another exchange. This allows reading, editing and accepting actual saved text.
7. **Profile update controllers:** Require DTO account ID to match the shared profile ID, preventing ownership reassignment through an otherwise owner-authorized update.
8. **Verification email link:** Points to frontend `/verify-email`, where the user's explicit confirmation sends the existing `GET /api/v1/account/verify-email` request. Token generation, expiry, hashing and throttling are unchanged.
9. **Uploaded regression test:** `ExchangeCompletionTests` now supplies the service's current Brevo/WhatsApp dependencies. Added isolated access-boundary tests. No email or WhatsApp sends occur in these unit tests.
10. **Deployment:** Added Dockerfiles, nginx same-origin proxy, Compose MySQL service, and a Windows environment-loading startup helper. No deployment was executed against an external host.

No hardcoded administrator or live test account is included. Browser validation uses real frontend HTTP calls and shows errors when infrastructure is absent.

11. **Supplied offer-evaluation addition:** Added `OfferEvaluationDtoIn` and `OfferEvaluationDtoOut` with the supplied fields/validation, the supplied `AIService.evaluateOffer` implementation, and `POST /api/v1/skill-offer/create/{skillId}/evaluate`. It uses existing active-account/verified-skill checks and AI helpers. It returns advice only; no offer save, price change, relationship change or token transaction occurs.

12. **Requested profile/logo file selectors:** Added narrowly scoped multipart image upload and public image read endpoints because the original backend only stored URL strings. Existing registration/profile paths, DTO fields and relationships are preserved. Raster validation, 2 MB input cap, generated names, image re-encoding and persistent filesystem configuration support the real upload flow. Uploads remain subject to mutation origin/header checks. Deployment needs the documented upload volume.

13. **Railway deployment integration:** Added configurable `PORT` and bind address, a public application-start health route, documented Railway service settings, and backend/frontend variable templates. The nginx frontend uses runtime backend-host/port variables, periodic private DNS resolution, preserved request methods/paths and HTTPS forwarding. Existing Docker Compose defaults still work. No pricing, exchange, relationship or authentication persistence rules changed.
